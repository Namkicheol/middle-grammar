# 교실 게임·결과 화면 QA 인수인계 — 2026-09-06

## 현재 구현 범위

- 교사는 Worker의 Google OpenID Connect와 자체 세션으로 인증한다. 운영 설정이 `TEACHER_SIGNUP_MODE=open`이면 Google이 검증한 이메일 계정을 일반 교사로 허용하며, `ADMIN_EMAILS`에 등록된 소유자는 관리자 역할을 유지한다. 관리자도 본인 방·리포트 소유권 범위를 벗어나지 않는다.
- 학생은 계정을 만들거나 로그인하지 않고 방 번호·닉네임으로 참가한다. 인증·CSRF·교사 세션 정책을 학생에게 우회 적용하지 않는다.
- 새 방은 `STUDENT_RECORD_RETENTION=session` 정책을 방 레코드에 캡처한다. 수업 중에는 Durable Object에 임의 player ID, 닉네임, 응답·점수·진행 상태, resume token 해시를 임시 보관한다. 종료 결과는 인증된 방 소유 교사와 해당 참가 학생이 30분 동안 확인할 수 있고, 이후 조회 또는 alarm에서 `deleteAll()`로 삭제한다. 시작하지 않은 대기실은 2시간 후 삭제한다.
- 세션 전용 방은 `room_reports`와 `player_results`에 결과를 쓰지 않는다. 기존 방과 과거 D1 리포트는 소급 삭제하지 않으며 기존 90일 정리 정책의 대상이다. 따라서 “학생 개인정보를 전혀 저장하지 않는다”거나 “과거 기록도 즉시 삭제됐다”고 설명하면 안 된다.
- 인증된 교사의 세션 전용 결과 조회는 소유한 Durable Object를 먼저 읽고, 기존 기록은 D1 조회로 fallback한다. 학생 결과 보존 설정은 교사 인증 identity·session 보존과 별개다.

## 서버 권위 교실 모드 6종

현재 `CLASSROOM_MODES`는 다음 여섯 가지다.

1. `boss_battle`
2. `bubble_battle`
3. `tower_race`
4. `rangers_siege`
5. `whack_race`
6. `sentence_blast`

서버가 현재 문항, occurrence, 정답 판정, 연속 정답 경쟁 점수와 공통 종료 시각을 결정한다. iframe 게임에는 정답이 포함되지 않은 안전한 문항만 전달하고, 제출 후 해당 학생의 판정 결과에만 `correctAnswer`를 포함한다. 클라이언트의 게임 성장 점수·연출은 서버 경쟁 점수와 별개다.

## 자동 검증 상태

- Worker: 145개 테스트 통과.
- 문항 은행: 5개 테스트 통과.
- 6개 교실 모드 각각에 대해 서버 권위 판정, 첫 정답 100점·두 번째 연속 정답 110점, timeout, duplicate·stale·deadline 거부, 정답 비공개 범위를 자동 테스트로 검사한다. 이 점수 자동 테스트와 아래 실제 브라우저 관측은 구분한다.
- 로컬 API transport E2E: `scripts/test-classroom-local-e2e.mjs`로 6개 모드 × 학생 2명 흐름을 확인했다.
- bridge와 native game adapter 정적 계약 검사를 통과했다. 대상은 보스전, 버블, 타워, Grammar Rangers, 두더지, Sentence Blast다.
- 학생 리뷰 반영:
  - Sentence Blast는 첫 서버 문항 뒤 문법 정답마다 8초간 실제 블록 플레이를 제공하며, 공통 종료 뒤 지연 보상 콜백이 게임을 다시 시작하지 않는다.
  - 두더지는 수업 모드에서 `1/1`, `2/2` 대신 실제 완료 기준 `푼 문제 N`을 표시한다.
  - 로컬 패배·보드 종료는 서버 수업이 진행 중이면 짧게 복구하고, 공통 종료 이벤트가 전체 입력과 루프를 멈춘다.

## 실제 브라우저 확인

Aside에서 실제 보스전 방 `803853` 한 건을 확인했다.

- 교사 시작 후 학생 화면이 자동으로 native iframe 보스전에 진입했다.
- 학생 자동화 진행 중 다음 문항 전환과 200점, 2/13 정답, 정답률 15% 렌더링을 관측했다.
- 교사 종료 버튼을 누르기 전에 공통 제한 시간이 자연 만료되어 결과 화면으로 전환됐다. 따라서 이 실행은 교사 수동 종료 검증이 아니다.
- 확인 구간에서 브라우저 오류는 없었다.

이 실행에서는 첫 단일 정답 직후 100점을 별도로 확인하지 못했다. 점검 중 예상값 100점과 관측값 200점 사이에 여러 timeout이 있었으며, 실제 클릭이 두 번 발생했는지 또는 중복 제출이 있었는지는 현재 interaction log 감사 중이다. 어느 쪽도 확인 전에는 원인으로 단정하지 않는다. 따라서 보스전의 단일 클릭 점수 처리는 미해결 브라우저 확인 항목이고, 나머지 5개 native 게임도 실제 브라우저 QA가 남아 있다. “6개 게임 모두 브라우저 통과”라고 보고하면 안 된다.

## 결과 화면 디자인 상태

단일 클릭 추가 진단: `scripts/test-boss-classroom-answer-flow.mjs`에서 실제 보스전 함수와 브리지를 VM으로 실행했다. 클릭 직후 timeout 경합은 두 번째 제출을 만들지 않으며, 동일 occurrence의 동시 제출도 거부됨을 확인했다. 이 검사는 실제 Aside 세션의 두 번째 정답 원인을 설명하지는 못하므로, 통제된 브라우저 재확인은 남겨 둔다.

- 학생 0명·1명·3명과 390px fixture에서 top 3 결과 시각 요소가 렌더링되는 단계까지 확인했다.
- 그러나 사용자가 현재 결과 UI를 다시 명확히 거절했다. 현재 CSS 단계는 승인본이 아니다.
- 새 전체 화면 이미지 mock preview는 생성됐지만 아직 제품 UI로 구현되지 않았고 사용자 승인도 받지 않았다.
- 현재 결과 UI나 새 mock을 운영 배포·커밋했다고 기록하면 안 된다. 이 문서 작성 시점에는 관련 배포·커밋이 없다.
- 새 시안은 어두운 체육관 전체 화면, 원통형 금·은·동 입체 시상대, 무대와 통합한 개인 기록판이다. GPT 이미지 생성으로 만든 예시 데이터 기반 시안이며 아직 실제 UI 구현물이 아니다.
