# 문법 아케이드 멀티플레이 MVP 설계

> 2026-09-06 변경: 이 문서의 Cloudflare Access 인증 계획은 [요금제 선택 없는 Google 직접 로그인 설계](2026-09-06-no-plan-teacher-auth.md)로 대체한다. 아래 MVP 기록은 당시 설계이며, Access 설치를 진행하지 않는다.

## 목표

기존 솔로 게임은 그대로 유지하면서, 교사가 방을 만들고 학생이 6자리 번호나 QR로 들어와 같은 문항 세트로 경쟁하는 `교실 점수전`을 추가한다. 교사는 전체 순위와 개인별 정답률을 확인하고, 학생은 로그인 없이 닉네임으로 참가한다.

## 범위

- 기존 게임 허브에 `혼자 하기 | 같이 하기` 진입을 추가한다.
- 솔로 허브는 `중1 | 중2`를 먼저 고른 뒤 게임과 Lesson을 고르는 3단계 구조로 바꾼다.
- 새 멀티플레이 화면은 학생 참가, 교사 방 만들기, 대기실, 진행 중 문제, 실시간 순위, 최종 리포트를 제공한다.
- 첫 모드는 `교실 점수전` 하나다. 교사는 제한 시간 1·3·5·7·10분, 반복 문항 묶음 10·15·20개, 중간 입장 허용 여부, 문제 순서 섞기 여부를 고른다.
- 교사 로그인은 Cloudflare Access의 Google 로그인을 사용한다. 허용 교사는 Access 정책에서 이메일로 관리한다.
- Quizlet, Excel, 사진, 직접 입력으로 문제 세트를 만드는 기능은 이번 MVP 뒤의 제작 기능 묶음으로 분리한다.
- 점수 뺏기·선물하기가 있는 `보물 약탈전`과 `암호 해킹전`은 교실 점수전 운영 검증 뒤에 추가한다.

## 화면 흐름

### 기존 허브

1. 첫 화면에서 `혼자 하기` 또는 `같이 하기`를 선택한다.
2. `혼자 하기`는 `중1 | 중2`를 먼저 선택한다.
3. 여섯 게임 중 하나를 선택하면 게임 목록은 한 줄 요약으로 접힌다.
4. L1~L8의 두 문법 주제 중 하나를 누르면 기존 솔로 게임으로 이동한다.
5. `전체 랜덤`은 각 학년 Lesson 목록 아래의 보조 선택지로 둔다.

### 학생

1. 방 번호 6자리와 닉네임을 입력하거나 QR 링크로 들어온다.
2. 대기실에서 참가자와 교사의 시작을 기다린다.
3. 제한 시간 동안 같은 문항 묶음을 교사의 설정에 따라 서로 다른 순서 또는 고정 순서로 반복해서 풀고, 본인 순위와 앞뒤 순위를 본다.
4. 종료 후 점수, 정답률, 맞힌 수, 평균 응답 시간을 확인한다.

### 교사

1. Google 로그인 후 학년, Lesson, 제한 시간, 반복 문항 묶음, 중간 입장, 문제 순서를 골라 방을 만든다.
2. 방 번호와 QR, 참가자 목록을 대형 화면으로 띄운다.
3. 시작·종료를 제어하고 전체 순위를 본다.
4. 종료 후 개인별 정답률과 응답 시간을 확인한다.

## 점수와 공정성

- 정답 기본 점수는 100점이다.
- 연속 정답 보너스는 `min(연속 정답 - 1, 5) × 10`점이며 한 문항 최대 150점이다.
- 오답은 0점이며 감점하지 않는다.
- 동점은 정답률, 맞힌 수, 평균 응답 시간 순으로 결정한다.
- 정답 검증, 점수 계산, 중복 제출 방지, 게임 시작·종료는 서버가 판정한다.
- 문항 묶음을 다 풀면 다음 cycle을 시작하며, 같은 문항 ID라도 새 `occurrenceIndex`이면 다시 풀 수 있다. 동일 occurrence의 재전송만 중복 제출로 거부한다.
- 학생에게 다른 학생의 정답률은 공개하지 않는다. 교사 화면에서만 전체 정답률을 본다.
- `중간 입장 허용`을 켜면 제한 시간이 끝나기 전 신규 참가자를 받고, 끄면 시작 뒤 참가를 거부한다.
- 같은 탭의 학생 재접속은 `sessionStorage`의 참가자 ID와 재접속 토큰으로 복구한다. WebSocket URL에는 토큰을 넣지 않고 서버가 발급한 60초 단일 사용 socket ticket만 넣는다.

## 기술 구조

- `/multiplayer/`: 의존성 없는 HTML/CSS/JS 클라이언트. 학생·교사 화면을 한 앱에서 역할별로 렌더링한다.
- `/multiplayer-worker/`: Cloudflare Worker + SQLite Durable Object. 방 하나를 Durable Object 하나에 대응시켜 WebSocket 연결과 방 상태를 직렬화한다.
- D1은 종료된 게임의 교사별 요약과 학생 결과를 저장한다.
- 서버 문항은 손수 관리되는 `game/questions.js`를 읽기 전용으로 파싱하는 빌드 스크립트로 생성한다. 원본은 수정하거나 재생성하지 않는다.
- 로컬 비운영 loopback 개발에서만 `X-Dev-Teacher-Email`을 허용한다. 운영 교사 API는 Cloudflare Access JWT의 서명·issuer·audience·email claim을 검증한 뒤 내부 교사 헤더를 만든다.
- 공개 학생 WebSocket은 외부 요청의 내부 신뢰 헤더를 폐기하고, 학생 socket ticket만 검증한다.

## 데이터 최소화

- 학생 계정은 만들지 않는다. 방 안에서만 쓰는 참가자 ID, 닉네임, 점수, 정오답, 응답 시간만 저장한다.
- 교사 이메일은 방 소유권과 리포트 조회에만 사용한다.
- 종료 결과는 90일 보존하며 매일 cron으로 만료된 D1 리포트와 학생 결과를 삭제한다. 방의 실시간 상태도 종료·방치 뒤 정리한다.

## 완료 기준

- 두 브라우저 세션에서 교사가 방을 만들고 학생이 번호로 참가한다.
- 교사가 시작하면 학생에게 문항이 나오고 답 제출 후 서버 계산 점수가 양쪽에 즉시 반영된다.
- 중복 답 제출은 점수를 두 번 올리지 않는다.
- 종료 뒤 교사와 학생에게 서로 다른 범위의 결과가 표시된다.
- 390×844 화면에서 가로 스크롤 없이 학생 참가와 기존 솔로 시작이 가능하다.
- 기존 여섯 솔로 게임의 링크와 `game/questions.js`는 유지된다.
